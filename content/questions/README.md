# Банк вопросов

Один файл — одна тема: `content/questions/<topic-id>.json`. Список тем — в [`../topics.json`](../topics.json). Схема — в [`src/lib/questions/schema.ts`](../../src/lib/questions/schema.ts).

После любых изменений запустите:

```bash
npm run questions:validate
```

## Формат файла

```json
{
  "topic": "js-core",
  "questions": [ /* вопросы */ ]
}
```

## Формат вопроса

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | `<topic>-<номер из 3 цифр>`, например `js-core-012`. **Никогда не меняйте и не переиспользуйте** — к id привязан прогресс |
| `level` | да | номер уровня внутри темы (1, 2, 3…), 5–10 вопросов на уровень |
| `difficulty` | да | `junior` / `middle` / `senior` |
| `tags` | нет | подтемы: `["closures", "scope"]` |
| `prompt` | да | вопрос так, как его задали бы на собеседовании |
| `code` | для `code_output` | `{ "lang": "js", "source": "..." }` |
| `answer` | да | эталонный ответ (markdown), 3–8 предложений, лучше с примером |
| `keyPoints` | для открытых форматов (минимум 2) | 2–5 пунктов, без которых ответ неполный — по ним работает чек-лист |
| `explanation` | да | объяснение при ошибке: почему правильно именно так, типичная ловушка |
| `formats` | да | в каких форматах можно показать вопрос (см. ниже) |
| `choices` | для `single_choice`, `multiple_choice` | `{ "correct": [...], "distractors": [...] }`; для `single_choice` ровно один правильный |
| `statements` | для `true_false` | `[{ "text": "...", "isTrue": true }]` |
| `codeOutput` | для `code_output` | `{ "answer": "1 4 3 2", "distractors": [...] }`, минимум 2 неправильных |
| `ordering` | для `ordering` | шаги в **правильном** порядке, минимум 3; при показе перемешиваются |
| `sources` | нет | ссылки на MDN или документацию |

## Форматы

`single_choice`, `multiple_choice`, `true_false`, `code_output`, `ordering` — проверяются автоматически.
`open_text`, `open_voice` — открытый ответ, проверка чек-листом по `keyPoints`.

**Правило:** почти каждый вопрос должен иметь хотя бы один автоматический формат (для первых показов) и `open_text` + `open_voice` (для закрепления). Исключение — темы `product-thinking` и частично `ai-product`, там допустимы только открытые форматы.

## Как писать хорошие вопросы

- Неправильные варианты — правдоподобные ловушки, а не очевидная чушь. Лучшие ловушки — типичные заблуждения.
- `keyPoints` — короткие проверяемые утверждения, не «рассказал про X», а «X делает Y».
- Один вопрос — одна идея. Если ответ занимает экран, разбейте на два вопроса.
- Факты проверяйте по MDN и официальной документации, ссылку кладите в `sources`.

## Промпт для генерации вопросов с AI

> Прочитай `PROJECT.md` и `content/questions/README.md`. Добавь в `content/questions/<topic>.json` вопросы с `<номер>` по `<номер>` для уровня `<N>` по подтемам: `<список>`. Уровень — Middle Frontend / Full-Stack собеседование. Соблюдай схему из `src/lib/questions/schema.ts`, продолжай нумерацию id. Затем запусти `npm run questions:validate` и обнови колонку «Сейчас» в таблице тем в `PROJECT.md`.

Сгенерированные вопросы обязательно вычитывайте: вычитка — тоже подготовка.
